# Backend — operating guide

Python backend for Cubik-IA: a guided calculus tutor delivered as an LTI 1.3 tool inside
Aula Extendida (Moodle 4.5). OpenSpec rules: `backend/openspec/config.yaml` (plus the
cross-cutting root `openspec/config.yaml`). No feature code outside an approved OpenSpec change.

## Stack
- Python 3.12+, dependencies managed with **uv** (`pyproject.toml` + `uv.lock`)
- **FastAPI** + **Pydantic v2** (+ `pydantic-settings` for config)
- **SQLAlchemy 2 async** + **Alembic**; PostgreSQL 16 (`asyncpg`) in dev/prod, SQLite (`aiosqlite`) in tests
- **SymPy** as CAS for deterministic math verification
- **LiteLLM** (library, not proxy) as model-normalization layer; initial provider **Gemini**
- Streaming to the frontend via **SSE**
- Tooling: pytest, pytest-asyncio, coverage, ruff (lint + format), mypy (strict), import-linter, Locust

## Architecture — modular monolith
One FastAPI service, split into feature modules with strict boundaries:

    backend/
      src/cubik/
        main.py                 # composition root: settings, wiring, app factory
        shared/                 # settings, logging, db session, base errors (no business logic)
        <module>/               # lti | identity | tutor | math | analytics
          api/                  # FastAPI routers + request/response schemas
          application/          # use cases / services; depends on Protocols only
          domain/               # entities, value objects, Protocols; no framework imports
          infrastructure/       # SQLAlchemy repos, LiteLLM, SymPy, Moodle/LTI clients
      migrations/               # Alembic
      tests/{unit,integration,benchmarks,load}

Rules:
- Dependencies point inward: `api -> application -> domain <- infrastructure`.
- `domain` imports nothing from FastAPI, SQLAlchemy, LiteLLM or SymPy.
- A module may use another module only through its `application` layer.
- Rules are enforced by import-linter contracts in `pyproject.toml` (part of `make check`).
- All wiring of Protocol -> implementation happens in `main.py` / FastAPI dependencies.
- LLM access only through the `LLMProvider` Protocol; model, fallback model and API keys come
  from settings (`LLM_MODEL`, `LLM_FALLBACK_MODEL`, provider key env vars).
- The LLM explains and scaffolds; correctness is decided by `MathVerifier` (SymPy) whenever possible.

## Contract
The OpenAPI document generated by FastAPI is the source of truth for frontend/. A snapshot
test fails on unintended contract changes; intended changes update the snapshot and open or
update the matching change in `frontend/openspec`.

## Testing
- TDD: failing test first, minimum implementation, refactor.
- Unit and integration tests never call real LLMs or Moodle — use `FakeLLMProvider`, a fake LTI platform, recorded fixtures.
- Coverage gate: >= 85% on `domain` and `application`.
- Math accuracy benchmark (`tests/benchmarks/`, versioned dataset, target >= 85%) hits the real model; run on demand, not in `make check`.
- Load tests with Locust (`tests/load/`).
- Every Alembic revision has a downgrade and is tested upgrade/downgrade on SQLite.

## Security & data protection
- Secrets only via environment variables (`backend/.env.example` documents them); never committed.
- LTI 1.3: id_token signature via platform JWKS, nonce/state validation, role mapping from LTI claims.
- Ley 1581 de 2012: LTI `sub` pseudonymized with keyed HMAC; store no name/email unless required; no PII or raw student text in logs.
- Review OWASP API Security Top 10 (2023) and OWASP Top 10 for LLM Applications for every change.

## Commands (Makefile)
Planned targets — created by the first OpenSpec change (backend skeleton):

| Target | Purpose |
|---|---|
| `make install` | `uv sync` |
| `make dev` | Run the API with reload |
| `make fmt` / `make lint` | ruff format / ruff check |
| `make typecheck` | mypy strict |
| `make imports` | import-linter |
| `make test` | pytest unit + integration with coverage gate |
| `make benchmark` | math accuracy benchmark (real LLM, costs money) |
| `make load` | Locust load test |
| `make migrate` / `make revision m="..."` | Alembic upgrade / new revision |
| `make check` | fmt check + lint + typecheck + imports + test |
