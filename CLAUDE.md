# Cubik-IA — operating guide (monorepo)

Guided calculus tutor (Cálculo Diferencial, Cálculo Integral, Métodos Numéricos, plus algebra
foundations per RF-04) delivered as an LTI 1.3 tool inside Aula Extendida (Moodle 4.5).
Cross-cutting OpenSpec rules: `openspec/config.yaml`.
Component guides: `backend/CLAUDE.md`, `frontend/CLAUDE.md`. No feature code outside an approved OpenSpec change.

## Purpose and cross-cutting constraints
- The assistant acts as a guided tutor (scaffolding, step by step), never as a direct homework solver. A complete
  solution is shown only after a recorded attempt and explicit student confirmation (RF-03).
- Ley 1581 de 2012: LTI user ids are pseudonymized at rest (keyed HMAC) and PII is minimized. Students see only their
  own history (RF-11); docentes see per-student data only for their own courses (RF-08, RF-10) and aggregated
  unit analytics (RF-09). Full visibility rules and the RNF quality targets: `openspec/config.yaml`.
- Requirements are cited by ID (RF-01..RF-14, RNF-01..RNF-09) from the SRS "Requerimientos funcionales y no
  funcionales - Cubik IA".
- The OpenAPI document generated by the backend is the contract between backend and frontend.
- Academic sources are cited by path and section. Today `docs/` has `Anteproyecto Trabajo de Grado.pdf`.
  The empty folders `docs/desing/`, `docs/interviews/` and `docs/polls/` are meant for the remaining
  sources (design mockups, interview transcripts, survey results); the SRS (IEEE 29148) has no file or
  folder yet. Cite a source only once its file exists: do not invent paths.

## Components and OpenSpec roots
- Three OpenSpec roots: `openspec/` (cross-cutting), `backend/openspec/`, `frontend/openspec/`. Each `config.yaml` holds the artifact rules for its scope.
- Run `openspec` from the directory of the root you target (nearest `openspec/` wins).
- Single-component work belongs to that component's root. Work spanning components (backend + frontend + Moodle LTI registration, compose, deployment) is a root change; root tasks cover only integration, infra and end-to-end verification.
- Read this guide and the guide of every component the change touches before starting.
- Slash commands `/opsx:explore|propose|apply|archive|sync|update` live in `.claude/commands/opsx`.

## OpenSpec flow
explore -> propose -> apply -> archive. Apply implements only what the change's tasks describe; new scope means updating the change first. Report verification results faithfully, including failures.

## Moodle boundary
- `moodle/` is the official code, unmodified. Configuration is `docker/moodle/config.php` (reads environment variables); data lives in Docker volumes.
- Integration only through LTI 1.3 / LTI Advantage and Moodle Web Services (REST). Never read Moodle's database directly.
- No custom plugins or themes in this phase; web plugin installs are disabled (`disableupdateautodeploy`), code is managed with Git.
- Update within 4.5 by replacing `moodle/` with the official `moodle-4.5.X.tgz` and running `admin/cli/upgrade.php`. Do not move to Moodle 5.x without reviewing its requirements.

## Local development
Needs Docker Engine 24+ (or Docker Desktop) with Compose v2. Local URL: <http://localhost:8085>.

```bash
cp .env.example .env                  # PowerShell: Copy-Item .env.example .env
docker compose up -d                  # first start installs Moodle (2-5 min)
docker compose logs -f moodle
docker compose ps                     # moodle must be "healthy"
docker compose stop                   # or: down (volumes are kept)
docker compose down -v                # DELETES the database and moodledata
docker compose exec -u www-data moodle php admin/cli/purge_caches.php
```

- Required in `.env`: `MOODLE_DB_PASSWORD`, `MOODLE_ADMIN_PASSWORD`, `MOODLE_ADMIN_EMAIL`.
- `MOODLE_WWWROOT` must match `MOODLE_HTTP_PORT` and the URL you type (`localhost`, not `127.0.0.1`); Moodle redirects to it.
- `MOODLE_ADMIN_*`, `MOODLE_SITE_*` and `MOODLE_LANG` apply only on the first install.
- The `cron` service runs `admin/cli/cron.php` every minute.

## Deployment
- Server: `docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d` adds Caddy (ports 80/443, automatic HTTPS) and needs `MOODLE_DOMAIN`. Guide: `docs/deploy-oracle.md`.
- Railway: `Dockerfile` + `railway.json`, health check `/healthz`. Guide: `docs/deploy-railway.md`.
- When services, config or deployment change, update compose, `.env.example` and `docs/deploy-*.md`.

## Environment and secrets
- Configuration through environment variables only. `.env` is gitignored (`.env.*` too, except `.env.example`); `.env.example` documents every variable with secrets left empty. Never commit real passwords.
- `MOODLE_DEBUG=false` outside development. Locally Moodle binds `127.0.0.1` (`MOODLE_HTTP_BIND`) over plain HTTP.

## Repo conventions
- `.gitattributes` forces LF for `*.sh` and `docker/**`: CRLF breaks the entrypoint scripts inside Linux containers.
- Git ignores `/moodle/config.php` (empty mount point Docker creates), `/frontend/node_modules/` and `/frontend/dist/`.
